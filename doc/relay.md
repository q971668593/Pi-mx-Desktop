# 自建中转（relay）：手机连电脑，不依赖第三方隧道

## 为什么需要它

手机在外网连电脑，现在靠三种办法：局域网、组网（Tailscale/ZeroTier）、公网入口（cloudflared / frp / 路由器端口映射）。
前两种要么要求同一个 Wi‑Fi，要么要求手机也装组网客户端；第三种依赖别人的服务，URL 会变，还经常被 VPN 规则带出国。

自建中转是你的第四条路，也是**推荐路线**：

- 一台你能控制的服务器（VPS）当中间人，电脑**主动连出去**注册，手机从任何网络连进来；
- 不装 cloudflared / frp，不用开端口映射，也不要求手机装 VPN；
- 手机到中转、电脑到中转都是普通 `wss://`（443 或任意端口），运营商和酒店网络都放行；
- 中转**只搬字节**：会话本来就是 X25519 + ChaCha20‑Poly1305 端到端加密，中转看不到内容，也冒充不了那台电脑。

## 关于「电脑开 VPN、手机不开」的延迟问题

说清楚这一点很重要：

| 角色 | 走的路 | 结论 |
|---|---|---|
| 手机 | 手机 → 中转（直连你的服务器） | 手机**不需要 VPN**，也不会被路由到国外 |
| 电脑 | 电脑 → 中转 | 只受电脑自己的 VPN 影响 |

如果电脑是**分流**（规则/大陆白名单）：把中转的域名或 IP 加进 VPN 的直连列表，电脑到中转就还是走本地出口。
如果电脑是**全局**（全部流量进隧道）：这段必然绕一圈，延迟由你的 VPN 出口决定 —— 这时把中转地址加进「绕过/排除」是最有效的一步。

几条实用建议：

1. **中转放在离你近的机房**（国内或香港/新加坡）：两端 RTT 都低，来回才快。
2. **电脑 VPN 里排除中转域名**：Clash 用 `- DOMAIN-SUFFIX,relay.example.com,DIRECT`；其它客户端用「直连/排除」列表。
3. **顺序**：手机是「局域网 → 组网 → 中转 → 手工公网入口」这一顺，到家自动走局域网，出门自动走中转，不用手动切。
4. 设置页会显示**电脑 → 中转**的心跳时延，数字突然变大就是被 VPN 绕路了，按上面第 2 条处理。

## 一条命令装好（推荐）

```bash
curl -fsSL https://raw.githubusercontent.com/q971668593/Pi-mx-Desktop/main/scripts/relay/install.sh   | bash -s -- --port 8443 --token <你自己的一串口令>
```

脚本会做这些（可以重复执行，不会重复装）：装 Node（缺了才装）→ 放 `server.mjs` 到 `/opt/pi-relay` → `npm i ws` →
写好 `relay.env`（口令 600 权限）→ 生成自签证书（有域名+`certbot` 就用 LE 证书）→ 注册 systemd `pi-relay` 并开机自启 →
本机 ufw/firewalld 放行端口 → 打印「中转地址 / 口令 / 证书指纹 / 下一步」。

不给 `--token` 会自动生成一个；`--port` 默认 8443；`--domain relay.example.com` 走公共证书。

**装完还差一步**：云控制台 → 防火墙/安全组 → 放行同一个 TCP 端口。这一步脚本碰不到（要云厂商的凭据），但不做外网就永远连不上。

桌面端里也有同样的向导：设置 → 手机连接 → 自建中转 → **展开向导**，点「生成口令」会得到一条带口令的完整命令，复制粘贴即可。

## 手动部署（5 分钟，想自己掌控每一步时看）

### 1. 起服务

```bash
# 服务器上（只需要 Node 18+ 和 ws）
npm i ws
RELAY_TOKEN=$(openssl rand -hex 24) node scripts/relay/server.mjs --port 8443 --token "$RELAY_TOKEN"
# 记住这个 $RELAY_TOKEN：设置页要填同一个
```

### 1.5 没有域名怎么办（自签证书 + 指纹）

手机平时靠「系统信任的公共证书」认中转；没有域名就没法签公共证书，那就换成**指纹固定** —— 和电脑端那张自签证书一个待遇：

```bash
node scripts/relay/server.mjs --port 8443 --self-signed --token "$RELAY_TOKEN"
# 首次会调用 openssl 生成 ./relay-tls/cert.pem 与 key.pem，并打印：
# [relay] 证书指纹(设置页点「检测证书」会自动取): 3nQ…
```

电脑端设置页 →「自建中转」填 `服务器IP:8443` 和口令 → 点 **检测证书** → 弹出指纹 → **信任并保存**。
之后配对链接里会带上这把中转证书的指纹（`relayTls`），手机连中转时认它；指纹不对就握不上手。

两份校验，两个方向都认指纹：

- **电脑 → 中转**：每次连之前先握一次 TLS 拿到叶子证书，指纹对不上就报 `relay_certificate_mismatch`（设置页状态里能看到），不会把口令递给陌生人；
- **手机 → 中转**：指纹随配对链接下发，手机只认这把。

要点：

- 证书只生成一次，指纹不会变（重装才变，重装后手机要重新扫码）；
- 中转地址是 IP 也行，自签证书没有合适的 hostname 也没关系 —— 手机认的是指纹；
- 指纹是 TOFU（第一次你看到的那个就是它），所以**第一次配置时确认一眼**：可以是你在服务器上 `node` 打印的那串。

### 2. 有域名就上公共证书（推荐）

用 Caddy 最省事（自动续期，顺便做反代）：

```
# /etc/caddy/Caddyfile
relay.example.com {
    reverse_proxy 127.0.0.1:8443
}
```

这时中转只监听本机：`--host 127.0.0.1 --port 8443`。
也可以让中转自己带证书（Let's Encrypt 签发即可）：

```bash
node scripts/relay/server.mjs --port 443 --cert /etc/letsencrypt/live/relay.example.com/fullchain.pem \
  --key /etc/letsencrypt/live/relay.example.com/privkey.pem --token "$RELAY_TOKEN"
```

### 3. 常驻

```ini
# /etc/systemd/system/pi-relay.service
[Unit]
Description=Pi relay
After=network.target

[Service]
Environment=RELAY_TOKEN=换成你的口令
ExecStart=/usr/bin/node /opt/pi-relay/server.mjs --host 127.0.0.1 --port 8443
Restart=always

[Install]
WantedBy=multi-user.target
```

`systemctl enable --now pi-relay` 之后，`curl https://relay.example.com/healthz` 应该回 `{"ok":true,...}`。

### 4. 电脑端填上

设置 → 手机连接 → 自建中转：

- 中转地址：`relay.example.com:443`（就是上面 Caddy/证书那个域名）
- 口令：`$RELAY_TOKEN`

保存后状态会变「已连接」，并显示心跳时延。手机不用做任何事 —— 下次连（或重新扫码）就会用上新的中转地址。

## 它是怎么工作

```
手机  ──wss──▶  relay.example.com:443  ◀──wss──  电脑（主动连出）
                    │  只搬字节，按房间号找宿主
                    └─ room: r_<24 字节随机>  ─ 写在配对链接里，猜不到就进不来
```

- 电脑启动网关时，`RelayAgent`（`src/main/remote/relay-agent.ts`）用口令连 `/host?room=…`，断了自动重连（1s → 30s 退避）。
- 手机连 `/c/<room>`，中转给它一个连接 id，让电脑在本地开一条回环连接（`ws://127.0.0.1:<端口>/ws`）——所以网关、鉴权、限速、配对逻辑一行都没改。
- 手机在电脑 ack 之前就发的握手帧会先被中转攒住，不会丢。
- 心跳：中转每 15 秒 ping 电脑，90 秒没 pong 就换连接；时延就是这两个包测出来的。

协议细节在 `packages/shared/relay.ts`（控制消息 JSON + 数据帧 `[flags][idLen][id][payload]`），
服务器实现在 `scripts/relay/server.mjs`（纯 .mjs，VPS 上不需要构建）。

## 阿里云轻量应用服务器（或任何一台 VPS）怎么配

以阿里云轻量为例，四步：

1. **放行端口**：轻量控制台 → 防火墙 → 添加规则，放行 TCP `8443`（用 443 就放 443）。服务器内部如果有 ufw/firewalld 也要放。
2. **装 Node**：`curl -fsSL https://deb.nodesource.com/setup_20.x | sudo -E bash - && sudo apt install -y nodejs`（或系统自带的 Node 18+ 也行；自签证书要用到 `openssl`，一般已自带）。
3. **传两个文件**：`scripts/relay/server.mjs` 放到 `/opt/pi-relay/`，`cd /opt/pi-relay && npm i ws`。
4. **起服务**（二选一）：
   - 有域名（`relay.example.com` 解析到这台机器）：挂 caddy 反代，走公共证书；
   - 没域名：`node server.mjs --port 8443 --self-signed --token <口令>`，走指纹固定。

内地域名的注意事项：阿里云内地节点用域名 + 80/443 提供网页服务需要 ICP 备案；**用 IP + 8443 + 自签证书这条路不涉及备案**，也不需要域名。想用公共证书又不想备案，就把轻量换成香港/新加坡节点（延迟仍然比走国外隧道低）。

验收：浏览器打开 `https://<IP>:8443/healthz`（会提示证书不受信任，正常）应该看到 `{"ok":true,...}`；
设置页点「检测证书」能拿到指纹、保存后显示「已连接」，手机连上来后「正在承载 1 台手机」。

**手机需要重新扫一次码**：中转地址和（自签时的）证书指纹都是写在配对链接里的，老的手机会话里没有这把指纹，只能继续走局域网。
同一台手机重新扫码不会丢项目/权限，只是刷新一下配对信息。

## 没有服务器怎么办

不用中转也能用，这些路都在（优先级：局域网 → 组网 → 中转 → 手工公网入口）：

| 办法 | 成本 | 代价 |
|---|---|---|
| 只在家里/同一个 Wi‑Fi 用 | 0 | 出门连不上 |
| Tailscale / ZeroTier（免费档够用） | 0 | 手机要装组网客户端、要登录账号 |
| 家里宽带有公网 IP + 路由器端口映射 + DDNS | 0 | 很多宽带已经是 CGNAT，拿不到公网 IP |
| 免费云（Oracle 免费 ARM、学生机等）或朋友的服务器 | 0 | 要自己部署一次，见上面四步 |
| 第三方隧道（cloudflared / frp） | 0 | URL 会变、依赖别人，还可能被 VPN 绕路 |
| 自己的轻量服务器 | 几十元/年 | 最稳，延迟最低 |

中转是「想更稳更快」的加法，不是「不用就用不了」的前提。

## 什么时候不用它

- 只在同一个 Wi‑Fi 用：不用配，局域网直连最快。
- 手机和电脑都装了 Tailscale/ZeroTier：组网地址已经能连，中转只是备份。
- 只是临时试一下：设置里「公网地址」填隧道域名仍然可用（就是现在 cloudflared/frp 那套）。

## 安全边界（会被谁看到什么）

| 谁能看到 | 看到什么 | 看不到什么 |
|---|---|---|
| 中转运营者（你自己） | 房间号、两端 IP、连接时长、每条连接收发多少字节 | 消息内容、文件内容、会话文件、项目名（全部在端到端加密层里面） |
| 网络中间人 | TLS 里的密文 | 同上；改一个字节 AEAD 校验就失败，连接直接断 |
| 拿到房间号但没配对的人 | 能连到中转，但握手过不去（电脑只认已配对设备/一次性配对码） | 任何数据 |

为什么中转冒充不了你的电脑：

1. 手机在扫码时拿到了电脑的**静态公钥**，握手是 Noise IK 形状：`k2 = HKDF(DH(e,C) ‖ DH(e,E) ‖ DH(C,E) ‖ DH(C,S))`。
2. 没有电脑静态私钥的一方算不出 `k2`，也就造不出能通过校验的 `hs2`——手机只会握手失败，不会把数据交出去。
3. 传输证书（Let's Encrypt 那张）只负责「不让运营商/酒店看流量」，不负责身份；身份由上面那把钥匙负责。

电脑端还有一层：设备要配对（一次性 5 分钟、用完即废的 `pair_used`）、可以随时解绑、只读/可操作两种权限分开。

**口令泄露的后果**：别人能用一个假宿主去占你的房间（拒绝服务），但依旧读不到内容、也冒充不了电脑——手机握手会失败。所以口令请用 24 字节以上随机串，泄露了就换一个（`--token` 改完电脑端设置页同步换），旧连接会被新连接顶掉。

中转本身也做了这些限制：口令定时比较（不给时间侧信道）、同一 IP 一分钟失败 10 次就 429、一个房间最多 64 条手机连接、最多 512 个房间、单帧 16MB、心跳 90 秒没响就换连接。

## 静态资源（图表 mermaid.min.js）

手机端要的静态资源走**会话通道**（RPC `asset.get`，1MB 一块，按 `host.hello` 里的 sha256 校验后落盘）。

- 经中转也能拿到（中转只转发 WebSocket，HTTP `/assets` 是不通的）；
- 全程是端到端加密的，不再有明文 HTTP 取脚本这一步；
- 老电脑端（没有 `asset.get`）才会退回旧的 HTTP 取法，同样校验哈希。

## 已知边界

- 中转上不落任何消息内容，也不做鉴权记录；唯一的凭据是口令（宿主）和房间号（手机）。
- 一个房间对应一台电脑的一条宿主连接；同一台电脑重连会顶掉旧连接，不会留僵尸。
- 中转是单进程内存态：重启会让所有手机瞬断（电脑端会自动重连，手机会跟着重试）。
